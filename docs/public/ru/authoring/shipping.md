## Тексты

Компонент должен получать собственные тексты, например названия кнопок для программ чтения с экрана, из каталогов своего пакета, а не из строковых литералов. Создайте в библиотеке пакет `locales/` с каталогом исходного языка и файлом для генерации кода:

```yaml
# locales/en.yaml
clear:
  message: Clear
  description: What screen readers say of the button that empties a chip input.
```

```go
// Package locales says the chips' words in the language the app shows.
package locales

//go:generate go tool nsgo i18n
```

Команда `go generate ./locales` создаёт функцию для каждого сообщения, которую компонент вызывает со своей областью (`Scope`): `locales.Clear(cx)` возвращает строку на текущем языке приложения. Включайте сгенерированный `catalog_gen.go` в коммиты, чтобы приложения собирались средствами одного лишь Go. Добавляйте по файлу на каждый язык, на который переводите библиотеку (`zh-Hans.yaml`); другие языки приложение может добавить в своих каталогах под ключом с путём импорта вашего пакета — так же, как для [собственных текстов NSGo](../localization.md#собственные-слова-nsgo).

## Тесты

`nsgotest` запускает компонент так, как с ним взаимодействует пользователь, в безголовом (`headless`) режиме. Смонтируйте его в небольшом корневом представлении и обращайтесь к нему по роли и тексту:

```go
func TestMain(m *testing.M) { nsgotest.Main(m) }

func TestToggle(t *testing.T) {
	app := nsgotest.Start(t, func(cx *core.Scope) core.Node {
		on := core.NewSignal(cx, false)
		return chips.Toggle{On: on.Get, OnChange: on.Set, Label: "Bold"}
	})
	app.Press("role:switch Bold")
	if !app.Find("role:switch Bold").Props.Checked {
		t.Fatal("the toggle did not turn on")
	}
}
```

Из корня библиотеки команда `go tool nsgo test` прогоняет все пакеты, а с флагом `-target macos` или другой целевой платформой запускает те же тесты в нативном окне. Проверяйте оба режима оформления и псевдолокаль (`-lang en-XA`), чтобы выявлять жёстко заданные цвета и непереведённые строки. Подробнее см. на странице [Тестирование](../testing.md).

## Публикация

Библиотека компонентов — это модуль Go: приложения подключают её через `go get` и импортируют её пакеты. Разделяйте нестилизованные и стилизованные варианты по разным пакетам, если в библиотеке есть оба, чтобы приложение с собственным дизайном не импортировало неиспользуемые стили.

Страница [Компоненты](https://nsgo.dev/components/) на сайте перечисляет библиотеки, которыми могут пользоваться другие разработчики; чтобы предложить свою, добавьте документ и скриншот в `docs/public/components/`.

Приложения на TSX получают доступ к Go-компонентам после их регистрации в функции `init`:

```go
func init() {
	tsx.Register("example.com/chips", map[string]core.Node{"Toggle": Toggle{}})
}
```

После этого `import { Toggle } from "example.com/chips"` принимает поля структуры в качестве пропсов ([Приложения на TSX](../tsx.md#go-из-tsx)).

## nsgo-module.yaml

Библиотека сообщает приложениям, которые её добавляют, всё, что им нужно знать, в `nsgo-module.yaml` — необязательном файле рядом с её `go.mod` в корне модуля, который [`nsgo add`](../building.md#добавление-библиотек) показывает в своём плане, прежде чем что-либо записать:

```yaml
version: 1
import: [player]            # пакеты, которые импортируют приложения, относительно корня модуля; . — корень
targets: [macos, windows_x64, linux_x64, ios, ios_simulator]
notes: |
  Библиотеки FFmpeg распространяются по LGPL 2.1: выкладывайте их исходный код рядом со своими загрузками, указывайте FFmpeg и позволяйте их заменять.
components:                 # пакеты, которые модуль предлагает скопировать
  chat: ui/chat
```

- `import` перечисляет пакеты, которые импортируют приложения; каждый — пакет этого модуля, а не вложенного в него модуля, и не пакет `main`. План выводит строку import для каждого, а без этого поля или без файла — строку корневого пакета.
- `targets` принимает имена и группы целевых платформ так же, как `build.targets`. План называет целевые платформы приложения, которых нет в списке, а `nsgo check -target` предупреждает о каждом модуле, который компонует приложение и в списке которого нет проверяемой платформы. Без этого поля ни то ни другое ничего не говорит о модуле.
- `notes` — простой текст не больше 4 КиБ без управляющих символов и символов форматирования, кроме переводов строки, — завершает план под строкой `From <module>, the author's notes:`, и каждая его строка помечена `|`: здесь место для того, чем обязано приложение, например для обязательств лицензии.
- `components` сопоставляет имена из 1–64 строчных латинских букв, цифр и дефисов, не начинающиеся и не заканчивающиеся дефисом, каталогам пакетов ниже корня модуля. Каждый каталог содержит пакет этого модуля, не являющийся пакетом `main`, и оканчивается именем своего пакета. План перечисляет каждый компонент с `nsgo add <module>#<name>`; nsgo пока не копирует компоненты и отклоняет эту команду.

Файл строгий: один документ YAML не больше 1 МиБ, версии 1, без якорей, псевдонимов и полей, которых nsgo не знает, и `nsgo add` отклоняет модуль, файл которого не может принять, с `-y` или без. Новые поля добавляются в версию 1, поэтому модуль, использующий такое поле, требует NSGo, который его читает, а более старый nsgo называет `go get github.com/nsgo-dev/nsgo@<версия>`, который приносит этот NSGo. `nsgo build` никогда не читает этот файл.
